# Dilian Jaars — Portfolio

A personal portfolio written in **TypeScript**: an Express server plus small
browser scripts, with hand-written HTML and CSS. Visitors see the home page
(with a book of websites they turn page by page), skills, services, contact and
a **Websites** page listing everything. The owner can add or delete websites
from the browser behind a single admin password.

The look is a risograph print: spot-colour inks on newsprint paper. Cyan, pink
and yellow mark skill groups, price lists and packages. Fonts are Anybody and Schibsted Grotesk, hosted in
`public/fonts/` under the SIL Open Font License.

## What's inside

```

  client/                Browser scripts (compiled to public/js/client/)
    book.ts                Home page: the book of websites (page turns)
    work.ts                Websites page: list and admin dialog
    contact.ts             Contact form (opens a ready-to-send email)
    site.ts                Footer year
    dom.ts                 Small typed DOM helpers
  shared/types.ts        Types used by both sides: WorkItem, Database, API shapes
public/                  What the server serves
  index.html, view-my-work.html (the Websites page), my-skills.html,
  my-services.html, get-in-touch.html, 404.html
  css/site.css             All styles; colour, type and spacing tokens at the top
  fonts/  images/          Fonts, your photo and the DJ logo
  uploads/                 Images added through the admin panel (not committed)
  js/                      Generated by `npm run build` (not committed)
data/db.json             Websites committed to the repo, as JSON
src/server/store.ts      Where websites are saved: Supabase, or local files
supabase/setup.sql       One-time Supabase table and image bucket setup
dist/                    Generated server build (not committed)
tsconfig.*.json          Strict TypeScript config for server and client
render.yaml              Render deploy config
.env.example             Copy to .env for local development
```

Old links still work: `/websites.html`, `/logos.html`, `/mockups.html` and
`/My-Services.html` redirect to their new homes. Logos and mockups were
removed; only websites remain.

## Run it locally

```bash
npm install
cp .env.example .env      # then set ADMIN_PASSWORD and SESSION_SECRET
npm run dev               # builds the browser scripts, then runs the server with auto-reload
```

Open http://localhost:3000. If `ADMIN_PASSWORD` is empty, admin login is
switched off and the site is read-only. After editing a file in `src/client/`,
run `npm run build:client` (or `npm run build`) to refresh the browser scripts.

| Command | What it does |
| --- | --- |
| `npm run dev` | Build browser scripts, run the server with auto-reload |
| `npm run typecheck` | Check all TypeScript without writing files |
| `npm run build` | Compile the server to `dist/` and the browser scripts to `public/js/` |
| `npm start` | Run the compiled server (run `npm run build` first) |

## The basketball gate

New visitors see a basketball game before any page of the site. They get 3
shots, and each is harder: the hoop moves, the wind pushes the ball, and from
shot 2 a defender blocks the lane. Each shot has a 10 second clock. Sinking one
basket lets them in (the browser sets a `dj_gate` cookie for the session). If
all three miss they can try again, and after two failed rounds (six misses) the
game lets them in anyway. Search engines and link previews skip it.

**Skip code:** "Skip with a code" asks for a code, checked on the server. The
default is `1234`; set `GATE_SKIP_CODE` in Render to change it. After 8 wrong
tries an IP is blocked for 15 minutes. This is a fun intro, not security: the
cookie is not secret, so anyone who sets it themselves gets in.

Files: `public/enter.html`, `public/css/gate.css`, `src/client/gate.ts` (the
game) and `src/client/hoop-physics.ts` (physics and level rules).

## The book of websites

The home page shows one two-page spread per website: the screenshot on the
left, the title, description, tools and a **Visit site** button on the right.
Visitors turn pages with **Previous page** and **Next page** (or the left and
right arrow keys). Newest sites come first. On phones it shows one page at a
time, and it skips the flip animation for people who ask their device for
reduced motion. With no websites yet it shows a "No websites yet" page.

## The admin panel

On the Websites page, **Manage** asks for the admin password. Once signed in
you can add a website (title, live link, screenshot, description, tools),
**edit** an existing one (change any field, replace or remove its screenshot) or
delete it. New sites appear in the book on the home page straight
away.

Security notes:

- There is **no default password**. `ADMIN_PASSWORD` must come from the
  environment. Set `SESSION_SECRET` too; without it the server uses a random
  secret and admin sign-ins end whenever it restarts.
- After 5 wrong passwords an IP address is locked out for 15 minutes.
- Uploads are limited to JPG, PNG, WebP and GIF (no SVG) up to 8 MB.
- Deleting an entry only removes files it uploaded itself. Images under
  `public/images/` are never deleted.
- Security headers (a strict Content Security Policy, `X-Frame-Options` and
  others) are set on every response. Scripts, styles and fonts only load from
  this site.

> If an earlier version of this repo with a hardcoded password was ever
> public, change `ADMIN_PASSWORD` to a new value. Git history keeps old code.

## Deploy: GitHub → Render

1. Push the repo to GitHub.
2. In [Render](https://render.com): **New → Blueprint** (or **Web Service**) and
   connect the repo. `render.yaml` fills in the settings:
   - Build: `npm install` (its `postinstall` step compiles the TypeScript, so
     a plain `npm install` or `yarn` build command also works)
   - Start: `npm start`
   - Health check: `/healthz`
3. In the service's **Environment** tab set `ADMIN_PASSWORD`. `SESSION_SECRET`
   is generated for you by the blueprint.
4. Deploy.

## Keep websites permanently with Supabase

Websites added in **Manage** are saved in a free Supabase project (database
plus image storage), so they survive redeploys and restarts.

1. Create a free project at supabase.com.
2. In **SQL Editor**, paste and run `supabase/setup.sql`. It creates the
   `websites` table and a public `portfolio` image bucket.
3. In **Project Settings → API**, copy the **Project URL** and a **secret /
   service_role key**.
4. In Render's **Environment** tab, add `SUPABASE_URL` and
   `SUPABASE_SERVICE_KEY`, then redeploy.

The key gives full access to the project, so keep it in Render only, never in
the repo. Without these two variables the site still works, but Manage saves
to local disk (see below). Entries in `data/db.json` always show too.

## Adding work so it lasts (without Supabase)

Render's free disk is **ephemeral**: entries added through the admin panel
(and their uploaded images) disappear when the service redeploys or restarts.
Two ways around that:

- **Commit your work to the repo (free).** Add your projects to
  `data/db.json` and put screenshots in `public/images/`, then push. Example
  entry:

  ```json
  {
    "id": "bakery-site",
    "title": "WeLove2Bake",
    "description": "A bakery site with a menu and order enquiries.",
    "url": "https://example.com",
    "tags": ["HTML", "CSS", "JavaScript"],
    "image": "/images/welove2bake.jpg",
    "createdAt": "2026-09-18T00:00:00.000Z"
  }
  ```

- **Use Supabase** (above, free).
- **Add a Render persistent disk** (paid) mounted on `data/` and
  `public/uploads/`, or move to a real database and image storage.

## Extra features

- **Estimate calculator** (Services page): built from the price rows marked `data-calc`, so prices live in one place; sends the choices to the contact form.
- **Website filter**: search box and tag chips on the Websites page (shown with 2+ websites).
- **SEO**: `public/sitemap.xml`, canonical/OpenGraph tags and JSON-LD. Update the domain there if it changes from dilian.online.
- **Polish**: scroll progress bar, back-to-top button, copy-email button, and a "Replay the game" footer link.
